# 用户-项目-数据库权限关系与存储隔离方案

## 1. 目标模型

| 关系 | 目标 |
| --- | --- |
| 用户 ↔ 项目 | 多对多。一个用户可参与多个项目，一个项目可有多个参与成员 |
| 项目 ↔ 数据库 | 一对一。一个项目绑定一个项目库，打开项目即获得该库，属项目级共享（成员都可查） |
| 用户 ↔ 文件 | 文件（代码、会话、记忆等 `.data` 下内容）是用户私有的：同一项目中各成员只能看到自己的文件，互相不可见 |
| `.data` 布局 | 由现在的 `.data/{appId}/` 单级，改为 `.data/{userId}/{appId}/` 两级 |
| chat 对话 | 前端保留传 dbName（有展示用途），后端以项目记录为准校验覆盖；打开项目即能获得项目库 |

## 2. 已确认决策

1. **成员角色粒度**：两级 owner/member，不做 viewer。owner 由 `app.owner`（项目创建人）表达，**不新增字段**；`app_member` 只存普通成员记录，不设 role 列。
2. **库名生成**：按现有逻辑不动 —— `create_app` 时用户填了 db_name 就建库，不自动生成、不加命名规则。
3. **CSV 目录**：项目目前实际未启用 CSV 功能，不在本方案范围内（出处与现状见 §3.4）。
4. **删除项目**：只删 app 记录；`app_member` 对应记录做逻辑删除（isDelete 置 1），不物理清理库与目录。
5. **前端 chat 请求**：保留 dbName 字段不动，后端校验时以项目记录为准。

## 3. 现状与差距分析

### 3.1 权限：单一属主，无成员概念

- `app` 表只有 `userId` 一个属主字段；`init/schema.sql` 中无成员表。
- app_service 所有接口都走 `_get_owned_app`（`backend/src/codegenx/app_service/services/app_service.py:329`）：非属主一律拒绝，admin 仅在查看详情（`_get_viewable_app`）时放行。**当前不存在"参与"语义，无法多人协作。**
- chat 链路无项目级权限：网关 `/api/chat/gen/code`（`backend/src/codegenx/gateway/api/chat.py`）只做登录校验 + 限流 + userId 注入，**任何登录用户可对任意 appId 发起对话**。
- 会话历史接口 `/api/ai/sessions/{app_id}`、`/messages`、`/alive`（`backend/src/codegenx/ai_service/router.py:126-175`）同样只校验登录，不校验用户与项目的关系。

### 3.2 数据库：库名由前端传入，后端不校验归属

- chat 请求体 `AiServiceGenerateRequest` 含可选 `dbName`（`backend/src/codegenx/ai_service/schema/ai_schema.py:18`），前端从 appInfo 取出后回传（`frontend/src/pages/app/AppChatPage.vue:1735`）。后端全程信任该值：`RuntimeSessionState.db_name` → `SessionContext` → 提示词注入 + `tool_executor` 自动填充工具参数（`backend/src/codegenx/ai_service/agent/tool_executor.py:91`）。**伪造 dbName 即可让 Agent 查询任意数据库**（MysqlManager 白名单默认不限制）。
- 表结构漂移：ORM `App` 已有 `db_name` 字段（`backend/src/codegenx/app_service/orm/app.py:21`），但 `init/schema.sql` 的 app 表 DDL 缺失 `dbName` 列。

### 3.3 存储：按 app 单级，无用户维度

- 路径函数集中在 `backend/src/shared/constants.py`（`get_runtime_app_dir/get_code_dir/get_deploy_dir/get_context_dir/get_memory_dir/get_session_dir/get_current_session_dir`），全部只接收 appId。现有 `.data/` 下即为 `10/1001/app1/...` 这类单级目录。
- 按此路径落盘且**跨用户共享**的内容（一旦放开成员参与就会互相可见）：
  - 代码/文件树：`.data/{appId}/code`（app_service 的 tree/file/save/upload/rename/delete/run 全套接口）
  - 会话：`SessionManager`（session_index.json 按 app 汇总，`backend/src/codegenx/ai_service/session/manager.py:184`）
  - 记忆：热记忆 MEMORY.md、暖记忆 topics（`backend/src/codegenx/ai_service/memory/hot.py`、`warm.py`、`paths.py`）
  - 任务看板：`TaskManager(app_id, session_id)`
  - 上下文/压缩大输出：`context/assembler.py`、`compact/large_output.py`
- `SessionContext`、`MemoryManager`、`TaskManager` 等运行时组件均未携带 user_id（`backend/src/codegenx/ai_service/context/session_context.py:18`），user_id 目前只用于监控打点与聊天记录标注。

### 3.4 CSV 目录的现状（不在本方案范围）

CSV 目录只出现在两处代码，均未实际生效：`CsvManager` 配置默认值 `/data/csv_files`（`backend/src/codegenx/ai_service/data_analysis/csv_manager.py:49`），以及 `context/assembler.py:53` 尝试读取 `settings.csv_data_dir` —— 但 `shared/config/config.py` 与 `.env.example` 中均无该配置项，也没有 CSV 上传入口。即 CSV 数据分析功能目前事实上未启用，本方案不处理；将来启用时再纳入 `.data/{userId}/{appId}/` 两级布局。

### 3.5 调用方清查（路径函数改动波及面）

`get_*_dir` 系列函数共 16 个文件调用：app_service、router（ai_service）、session/manager、memory（hot/warm/paths）、context/assembler、context_utils、task_manager、compact/large_output、agent（tool_executor/subagent_runner）、monitor（session_recorder/maintenance_service）、schedule/memory、shared/constants 本身。路径函数签名调整需同步这些调用点。

## 4. 总体设计

### 4.1 权限关系

- 新增**项目成员表 `app_member`**（DDL 已放入 `init/schema.sql`）：`(appId, userId)` 唯一，只存普通成员；项目属主直接看 `app.userId`，不写副本。
- 权限判定规则：owner = `app.userId` 为当前用户；member = `app_member` 有未删除记录；admin 平台管理员。

| 操作 | owner（app.owner） | member（app_member） | admin | 非成员 |
| --- | --- | --- | --- | --- |
| 查看项目详情/项目库表 | ✓ | ✓ | ✓ | ✗ |
| chat 对话 / 会话历史 / 文件读写 / 运行脚本 | ✓（自己的目录） | ✓（自己的目录） | ✓ | ✗ |
| 修改项目（改名） | ✓ | ✗ | ✓ | ✗ |
| 成员管理（邀请/移除成员） | ✓ | ✗ | ✓ | ✗ |
| 删除项目 | ✓ | ✗ | ✓ | ✗ |

- 权限校验收口到两个入口：
  - app_service：`_get_owned_app`（管理类，owner/admin）与 `_get_viewable_app`（参与类，成员即可）之间按上表拆分语义。
  - gateway chat（gen/stop）：提交前校验登录用户是 appId 的 owner/member/admin。
- ai_service 会话历史三个接口同样增加成员校验 + 用户维度路径（见 4.4）。

### 4.2 数据库绑定

- app 表补 `dbName` 列（DDL 已加）；建库逻辑保持现状：`create_app` 时用户填了 db_name 才建库。
- chat 请求的 `dbName` 字段前端照常传，**后端以 app 记录解析结果为准**：不一致时覆盖为项目库，堵住伪造 dbName 查任意库的口子。
- 增强（可选，后续）：MysqlManager 按会话绑定项目库，将当前项目库作为该会话工具查询的白名单。

### 4.3 存储两级目录

- `shared/constants.py` 全部路径函数签名改为 `(userId, appId)` 两级：`.data/{userId}/{appId}/` 下仍分 `code/deploy/context/memory/session`。
- 运行时链路携带 user_id：`AiServiceGenerateRequest.user_id`（已存在）→ `RuntimeSessionState` → `SessionContext` → `SessionManager/MemoryManager/TaskManager/ContextAssembler`，凡取路径处都带 user_id。
- app_service 文件类接口从登录态取 userId 定位目录（前端无需传）。

## 5. 改动清单（不含代码）

### 5.1 表结构（`init/schema.sql`，本次已改好，可全量删表重建）

- app 表精简并改列：`owner`（原 `userId` 改名，即项目创建人）+ `dbName`；同时移除废弃字段 `initPrompt/cover/codeGenType/deployKey/deployedTime/priority`。
- 新增 `app_member` 成员表（无 role 列，`(appId, userId)` 唯一，逻辑删除）。
- 对应 ORM：app_service 下 `App` 精简重写 + 新增 `AppMember` 模型。

### 5.2 app_service（`backend/src/codegenx/app_service/`）

- 权限判定收口到新文件 `services/access.py`：`get_access_role`（owner/member/admin）、`require_participant`（参与类）、`require_manager`（管理类）、`require_participant_by_id`（gateway/ai_service 复用）。
- `create_app`：属主写 `app.owner`，并初始化 `get_code_dir(owner, appId)` 目录；不写成员记录。
- `delete_app`：owner/admin 可删；物理删除 app 记录 + 逻辑删除 `app_member` 中该项目全部记录。
- `update_app / admin_update_app`：维持 owner/admin（仅改名）。
- `list_my_app_vo_by_page`：查询条件由"owner = 当前用户"扩展为"属主或未删除成员"（`or_(App.owner == uid, App.id.in_(member_app_ids))`）。
- 文件全套接口（tree/读/写/建/传/删/改名/运行/下载/db tables）：统一 `_get_participant_app` 成员校验，路径取 `当前登录用户 + appId`。
- 新增成员管理接口：`GET /app/member/list/{appId}`、`POST /app/member/add`（支持按 userAccount 或 userId 邀请）、`POST /app/member/remove`（逻辑删除；重新加入恢复原记录，满足 uk_app_user 唯一键）。
- 移除 `/good/list/page/vo` 精选列表接口（priority 字段已删）。
- schema：新增 `AppMemberAddRequest/AppMemberRemoveRequest/AppMemberVO`；`AppVO` 精简为 `id/appName/owner/dbName/createTime/updateTime`。

### 5.3 gateway（`backend/src/codegenx/gateway/api/chat.py`）

- gen/stop 两个端点：注入 userId 之后，增加"用户是 appId 的 owner/member/admin"校验；gen 端点由后端从 app 记录解析 db_name 并覆盖请求字段（前端传值仅参考）。

### 5.4 ai_service（`backend/src/codegenx/ai_service/`）

- `router.py` 会话历史三端点：加成员校验，路径加 userId 维度。
- `session/manager.py`：`SessionManager` 构造与 `read_session_index` 增加 userId 参数，session_index.json 随目录自然按用户隔离。
- `context/session_context.py`、`context/assembler.py`、`utils/context_utils.py`：透传 userId，`build_workspace`、`ensure_app_workdir` 等改用两级路径。
- `memory/`（paths/hot/warm、MemoryManager）、`task/task_manager.py`、`compact/large_output.py`、`agent/subagent_runner.py`、`agent/tool_executor.py`、`monitor/`（session_recorder/maintenance_service）、`schedule/memory.py`：路径调用补 userId。

### 5.5 shared

- `constants.py`：路径函数两级化（核心改动）；`get_deploy_dir`/`APPS_DIR`/`APPS_CODE_DIR`/`APPS_DEPLOY_DIR` 等遗留常量与函数已删除。

### 5.6 前端（`frontend/src/`）

- chat 发送请求**保留 dbName，不改**（后端会覆盖，仅前端展示用途）。
- 项目列表页改为"我参与的项目"；卡片展示 `项目库：dbName`（替代原 initPrompt 摘要）。
- 新增成员管理入口：成员弹窗（按账号邀请 / 成员列表 / 移除，移除按钮仅属主可见）。
- 新增成员接口封装 `api/app.ts`：`listAppMembers / addAppMember / removeAppMember`（经 `appController.ts` 别名导出）。
- `HomePage` 编辑弹窗仅改项目名；`AppEditPage`/`AppManagePage` 移除 initPrompt/cover/priority/deployKey 相关表单与列。
- 类型定义同步：`AppVO` 精简（owner/dbName），新增 `AppMemberVO`，删除 `AppChatRequest/priority/deployKey` 等废弃类型。

### 5.7 移除的功能（随字段精简一并清理）

app 表删除 `deployKey/deployedTime/priority` 等列后，以下功能整体移除（前后端 + 文档）：

- **发布 deploy 功能**：后端 `/app/deploy`、`/app/static/{deployKey}/*` 静态资源端点、`get_deploy_dir` 及部署目录常量；前端 `deployApp`/`serveStaticResource*` API、`getDeployUrl/getStaticPreviewUrl/STATIC_BASE_URL/DEPLOY_DOMAIN` 配置、`DeploySuccessModal.vue`、`AppCard.vue` 的"查看作品"入口（`AppCard.vue`/`AppDetailModal.vue` 已无引用，直接删除）。
- **priority 优选/精选**：后端 priority 字段与 `/app/good/list/page/vo`；前端 `AppManagePage` 精选开关（toggleFeatured）与 `listGoodApps` API。
- **initPrompt 初始提示词**：后端字段与自动触发链路；前端创建/编辑/管理页表单项、`AppChatPage` 首条自动发送（`sendInitialMessage`/autoGenerateInitialMessage 管道）。
