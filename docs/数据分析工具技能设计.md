# 数据分析 Tool 和 Skill 设计

> **设计原则**：只做生成不做执行 —— Tool 层负责读取元数据和采样，Skill 层负责指导模型生成分析代码。生成的 SQL/Python/图表代码由用户自行执行。
>
> **实现路径**：Tool 类放到 `bot/tools/` 下（继承 `BaseTool`），Skill 放到 `bot/skill/<skill-name>/SKILL.md`。MySQL 连接管理和文件读取的实际执行放到 `bot/data_analysis/` 下作为 manager。

---

# 一、Tool 设计

所有 Tool 均继承 `BaseTool`，参数用 JSON Schema 定义。每类数据源（MySQL / CSV）各有一组工具，命名规约清晰区分。

## 1.1 MySQL 工具

### 1. list_tables(db_name)
返回指定库下所有表的信息，拼接为字符串：
- 表名
- 表注释/说明
- 行数估算（从 information_schema 获取，避免全表扫）
- 表级描述

通过 `SHOW TABLES` + `information_schema.TABLES` 组合实现。

### 2. describe_table(db_name, table_name)
返回单表结构信息，拼接为字符串：
- 列名、数据类型、是否可空、默认值、列注释
- 行数（估算）、列数
- 表注释/描述
- 主键、索引信息（索引名、类型、涉及列）

通过 `SHOW CREATE TABLE` + `information_schema.COLUMNS` + `information_schema.STATISTICS` 组合实现，格式化后返回。

### 3. sample_rows(db_name, table_name, limit=10)
返回表的采样数据，用于让模型理解字段值类型和典型内容。默认 10 行，可调整。
- 列名作为表头
- 每行数据格式化对齐（长文本截断到 200 字符）
- 返回格式：markdown 表格或对齐的纯文本

通过 `SELECT * FROM {table} LIMIT {limit}` 实现。

### 4. describe_table_stats(db_name, table_name, columns=None, sample_pct=100, timeout_seconds=30)
返回更详尽的统计信息，拼接为字符串：
- **数值字段**：count、mean、std、min、25%/50%/75% 分位数、max
- **类别字段**：唯一值数量、最高频 TOP 10 取值及频率
- **时间字段**：最小/最大时间、时间跨度
- **缺失情况**：每列缺失数量及占比
- **列间相关性提示**：数值列之间 Pearson 相关系数 TOP N（绝对值排序），仅提示不展开

通过针对每列生成对应聚合 SQL（`COUNT`/`AVG`/`STDDEV`/`MIN`/`MAX` 等）批量执行实现。

**大表 / 宽表应对策略**（由 MysqlManager 内部执行，对调用方透明）：

1. **行数过多（> 100 万行）**：
   - `sample_pct` 默认 100（全量），自动降级：100万-500万行 → 自动降为 30%；500万-1000万 → 10%；> 1000万 → 1%
   - 降级时在返回结果开头标注：`[采样率 10%，全量约 800 万行]`
   - 分位数计算（MEDIAN/PERCENTILE）在大表上成本很高，采样模式下用近似算法（`PERCENT_RANK` + `WHERE pct BETWEEN 0.24 AND 0.26` 取近似中位数），并在结果中标注 `≈`

2. **列数过多（> 30 列）**：
   - `columns` 为 None 时，自动选列策略：优先数值列 → 时间/日期列 → 低基数列（distinct < 100）→ 文本列跳过
   - 最多统计 **20 列**（超出部分截断），并在末尾标注跳过的列名列表
   - 用户可通过 `columns` 参数精确指定要统计的列

3. **超时保护**：
   - 单个统计查询超过 `timeout_seconds`（默认 30s）时，终止该列的统计，返回已计算的部分结果 + `[超时，以下 X 列未完成统计: ...]`
   - 各列统计独立执行，一列超时不影响其他列

4. **相关性计算**：
   - 仅在全量模式（sample_pct=100）且数值列 ≤ 10 时计算
   - 采样模式下跳过相关性，标注 `[相关性需全量数据，使用 sample_pct=100 可开启]`

5. **去重保护**：
   - 类别字段统计时，DISTINCT VALUES 计算限制扫描行数 = MAX(总行数 × sample_pct, 100万)，超过后标注 `[去重统计已截断]`

## 1.2 CSV 工具

### 5. describe_csv(file_path)
返回 CSV 文档的基本信息，拼接为字符串：
- 文件路径/名称、文件大小
- 行数、列数
- 列名、推断的数据类型（pandas dtype）
- 每列缺失值数量及占比
- 前 5 行样本数据
- 编码（自动检测）、分隔符

通过 pandas 读取 + 自动编码检测实现。

### 6. sample_csv_rows(file_path, limit=10)
返回 CSV 的采样数据，与 `sample_rows` 格式一致，让模型理解字段值类型和典型内容。默认 10 行，可调整。

### 7. describe_csv_stats(file_path, columns=None, sample_pct=100, timeout_seconds=30)
返回 CSV 的详尽的统计信息，与 `describe_table_stats` 输出格式一致：
- **数值字段**：count、mean、std、min、25%/50%/75% 分位数、max
- **类别字段**：唯一值数量、最高频 TOP 10 取值及频率
- **时间字段**：最小/最大时间、时间跨度
- **缺失情况**：每列缺失数量及占比
- **列间相关性提示**：数值列之间 Pearson 相关系数 TOP N

通过 pandas `describe()` + 自定义统计实现。

**大表 / 宽表应对策略**（由 CsvManager 内部执行，对调用方透明）：

1. **行数过多（> 50 万行）**：
   - 自动降级采样：50万-200万 → `sample_pct` 降为 30%；> 200万 → 10%
   - 降级时返回结果开头标注：`[采样率 10%，全量约 300 万行]`
   - 分位数由 pandas `describe(percentiles=...)` 在采样数据上计算，标注 `≈`

2. **列数过多（> 50 列）**：
   - `columns` 为 None 时自动选列：数值列优先 → 时间/日期列 → 低基数列（unique < 100）→ 跳过纯文本列
   - 最多统计 **30 列**，跳过列在末尾列出
   - 用户可通过 `columns` 精确指定

3. **超大文件（> 500MB）**：
   - 禁止全量读取，强制采样（按文件大小比例：500MB→20%, 1GB→10%, >2GB→5%）
   - 采样从文件头部跳过随机偏移后顺序读取（不等距采样，避免 seek 风暴）

4. **超时保护**：
   - 单文件统计超过 `timeout_seconds`（默认 30s）时终止，返回已计算结果 + `[超时，以下 X 列未完成]`

5. **相关性计算**：
   - 仅在全量模式且数值列 ≤ 15 时计算
   - 采样模式下跳过，标注 `[相关性需全量数据]`

## 1.3 通用辅助工具（建议新增）

### 8. guess_analysis_task(db_name=None, table_name=None, file_path=None)
根据数据结构自动推断可能的分析方向，让模型在用户需求模糊时能主动引导：
- 有明确时间列 + 数值列 → 建议时序分析、同比环比
- 有类别列 + 数值列 → 建议分组对比、排名
- 有多表关联 → 建议关联分析
- 文本列多 → 建议文本分析/分类
- 返回 3-5 条分析方向建议

这个工具是可选的，用于提升"用户不知道怎么分析"场景下的体验。

### 9. get_table_relationships(db_name)
返回库中表之间的外键关系和可能的关联推断：
- 显式外键（从 information_schema 获取）
- 列名相似度推断（如 `user_id` / `id`，给出 "可能关联" 的提示）
- 返回关联关系列表

用于辅助模型理解多表 JOIN 场景。

# 二、Skill 设计

每个 Skill 是 `bot/skill/<name>/SKILL.md`，包含 YAML frontmatter（name、description、metadata）和 Markdown 正文。Skill 正文是给 LLM 的系统提示，告诉它：何时触发、可用哪些工具、分析步骤、输出约束、最佳实践。

## 2.1 sql_analysis_skill

**适用场景**：用户需要生成数据分析 SQL 语句。

**核心步骤**：
1. **了解表结构** → 调用 `list_tables` 确定有哪些表，找到相关表
2. **深入字段理解** → 调用 `describe_table` 获取字段名、类型、注释；调用 `sample_rows` 查看实际数据样例
3. **理解表关系** → 调用 `get_table_relationships` 确定 JOIN 关系；如无明确外键，通过字段名模式推断（`xxx_id` → `id`）
4. **明确需求** → 如果用户需求不清晰，主动用 `guess_analysis_task` 生成建议方向让用户选择；需要确认的：聚合粒度（按天/周/月？）、过滤条件、排序要求、结果行数限制
5. **生成 SQL** → 写出完整可运行的 SQL，包含注释说明每段逻辑
6. **代码说明** → 简要说明 SQL 做了什么、关键逻辑（为什么用这个 JOIN 类型、为什么用窗口函数等）

**SQL 生成约束**：
- 优先使用 CTE（WITH 子句）组织复杂查询，而非嵌套子查询
- 大表查询必须带 LIMIT，默认 1000 行
- 时间范围查询必须明确起止日期占位符
- 聚合查询注意除零保护（NULLIF / COALESCE）
- 字符串匹配优先用 LIKE 而非正则（可移植性）
- 窗口函数用于排名、累计、移动平均等场景
- 生成的占位符用 `{start_date}`、`{end_date}`、`{top_n}` 等标记，方便用户替换

**输出格式**：
````
## 分析思路
<简要说明分析逻辑>

## SQL 代码
```sql
-- <注释说明>
WITH ... AS (...)
SELECT ...
FROM ...
WHERE ...
```
````

## 2.2 python_analysis_skill

**适用场景**：用户需要生成 Python（pandas/numpy）数据分析代码。

**核心步骤**：
1. **确定数据源** → MySQL 表还是 CSV 文件
2. **了解数据结构** → MySQL：调用 `describe_table` + `sample_rows`；CSV：调用 `describe_csv` + `sample_csv_rows`
3. **确认分析目标** → 和用户确认：描述性统计？分组对比？趋势分析？异常检测？关联分析？
4. **生成代码** → 根据分析类型生成对应代码，包含：
   - 数据加载（`pd.read_sql` 或 `pd.read_csv`）
   - 数据清洗（缺失值处理、类型转换）
   - 分析逻辑（聚合、透视表、统计检验等）
   - 结果输出（print、to_csv、to_excel）

**代码生成约束**：
- 数据加载后第一步打印 `df.info()` 和 `df.head()` 确认数据正确
- 缺失值处理要有明确依据：数值型用中位数/均值、类别型用众数/"未知"、时间序列用前向填充
- 所有聚合操作考虑 `dropna()` 的影响
- 处理大数据集时提示 `chunksize` 分块读取方案
- 日期/时间列统一用 `pd.to_datetime` 转换，指定 `format` 提高性能
- 代码中关键步骤添加注释说明 WHY（为什么这样清洗、为什么选这个统计方法）

**输出格式**：
````
## 分析思路
<分析逻辑>

## 数据加载
```python
# 加载数据的代码
```

## 数据清洗
```python

## 2.3 plot_skill

**适用场景**：用户需要生成数据可视化代码。

**核心步骤**：
1. **确认绘图目标** → 用户想看什么？对比、分布、趋势、构成、关系？
2. **了解数据** → 调用 `describe_table`/`describe_csv` + `sample_rows` 获取字段信息
3. **选择图表类型** → 根据字段类型和分析目标自动推荐（见下方图表选择指南）
4. **生成绘图代码** → 使用 matplotlib/seaborn/plotly，包含完整的数据准备 + 绘图 + 样式设置

**图表选择指南**（需写入 Skill 正文）：

| 分析目标 | 适用图表 | 适用数据类型 |
|---------|---------|------------|
| 比较数值大小 | 柱状图、条形图 | 类别 × 数值 |
| 展示占比/构成 | 饼图、环形图、堆叠柱状图、树图 | 类别 × 数值（≤ 6 类饼图，更多用柱状图） |
| 展示数据分布 | 直方图、箱线图、小提琴图 | 数值列 |
| 展示变化趋势 | 折线图、面积图 | 时间 × 数值 |
| 展示关系/相关性 | 散点图、气泡图、热力图 | 数值 × 数值 / 多变量 |
| 排名 | 条形图（排序） | 类别 × 数值 |
| 多维度对比 | 分组柱状图、雷达图、平行坐标 | 类别 × 多数值 |
| 地理空间 | 地图、等值线图 | 经纬度 × 数值 |

**代码生成约束**：
- 默认使用 plotly（交互式），用户明确要静态图时用 matplotlib/seaborn
- 中文字体设置（matplotlib：`plt.rcParams['font.sans-serif'] = ['SimHei']`，plotly：`title_font=dict(family='SimHei')`）
- 颜色方案：分类用 Set2/tab10，连续用 Viridis/Blues，避免红绿对比（色盲友好）
- 图表必须包含：标题、坐标轴标签、图例（多系列时）
- 数值标签：柱状图顶部、饼图显示百分比
- 代码结构：先用 pandas 做数据聚合，再传入绘图函数（数据和绘图分离）
- 生成的图表尺寸默认 (12, 6)，适配屏幕阅读

**输出格式**：
````

## 2.4 feature_engineering_skill

**适用场景**：用户要做特征工程（用于机器学习建模前的数据预处理）。

**核心步骤**：
1. **确认目标** → 目标变量是什么？任务类型（分类/回归/聚类/时间序列）？
2. **了解数据** → 调用 `describe_table`/`describe_csv` + `sample_rows` + `describe_table_stats`/`describe_csv_stats` 获取数据概况
3. **识别各列特征类型** → 数值 / 类别 / 时间 / 文本 / 缺失严重列 / 常量列
4. **按类型输出处理建议 + 代码** → 每类特征给出处理方案
5. **提示注意事项** → 数据泄露、训练/测试分离时机等

**各类型特征处理指南**（需写入 Skill 正文）：

### 缺失值处理
| 场景 | 方法 | 适用条件 |
|------|------|---------|
| 缺失 < 5% | 直接删除行 | 样本量充足 |
| 缺失 5%-30% | 填充（数值→中位数/均值，类别→众数/"未知"） | 大部分场景 |
| 缺失 30%-60% | 增加"是否缺失"标志列 + 填充 | 缺失本身可能是信号 |
| 缺失 > 60% | 直接删除该列 | 信息量不足 |
| 时间序列缺失 | 前向填充 / 线性插值 / 时间加权均值 | 保持时间顺序 |

### 数值特征
- **标准化**（StandardScaler）：适用于假设数据正态分布的模型（线性回归、SVM、神经网络）
- **归一化**（MinMaxScaler）：适用于基于距离的模型（KNN、K-Means）
- **分箱/离散化**：从连续值创建类别，增强可解释性
- **对数变换**：处理长尾分布（偏度 > 1）
- **异常值处理**：IQR 法（Q1-1.5×IQR, Q3+1.5×IQR）/ 百分位数截尾（1%/99%）
- **多项式特征**：生成交互项和平方项，适用于存在非线性关系的场景

### 类别特征
- **低频合并**：频率 < 1% 的类别合并为"其他"
- **目标编码**（Target Encoding）：用目标变量的均值编码类别（注意 K-Fold 防泄漏）
- **One-Hot 编码**：类别数 < 20，树模型用
- **标签编码**（Label Encoding）：类别数 > 20，或有序类别
- **频数编码**：用出现次数替代类别值

### 时间特征
- 从时间戳中提取：年、月、日、星期、小时、季度
- 周期性编码：`sin(2π×hour/24)`、`cos(2π×hour/24)` 保留周期信息
- 距关键日期天数：距最近节假日、距今天数
- 滑窗聚合：过去 N 天的均值/最大值/计数

### 文本特征
- 文本长度、词数统计
- TF-IDF / CountVectorizer（简单场景）
- 关键词/正则匹配生成标志列
- 提示：深度文本理解需专门的 NLP 流程

### 通用注意事项
- **数据泄露**：任何基于目标变量的编码必须在训练集上拟合、然后 transform 到测试集
- **先拆分再处理**：所有 fit（标准化、编码）必须在训练集上做，再 apply 到测试集
- **高基数类别**（> 50 类）：避免 One-Hot，用目标编码或频数编码

**输出格式**：
````
## 数据概况
- 总行数/列数
- 缺失情况汇总
- 数据类型分布

## 各列处理建议
| 列名 | 类型 | 缺失率 | 处理方案 | 理由 |
|------|------|--------|---------|------|

## 特征工程代码
```python
# 按处理顺序组织：缺失值 → 异常值 → 编码 → 标准化 → 特征构造
```
````

## 2.5 modeling_skill

**适用场景**：用户需要生成机器学习建模代码。

**核心步骤**：
1. **确认任务类型** → 分类（二分类/多分类）、回归、聚类、时间序列预测？
2. **了解数据** → 调用 `describe_table`/`describe_csv` + `sample_rows` + `describe_table_stats`/`describe_csv_stats`
3. **推荐模型 + 理由** → 根据数据规模、特征类型、任务目标推荐 2-3 个候选模型
4. **生成完整建模代码** → 包含数据准备、模型训练、评估、预测

**模型选择指南**（需写入 Skill 正文）：

### 分类任务
| 场景 | 推荐模型 | 理由 |
|------|---------|------|
| 需要可解释性 | 逻辑回归 / 决策树 | 系数/规则透明，可解释性强 |
| 特征多、样本量大 | XGBoost / LightGBM | 梯度提升，性能优秀 |
| 样本量小但特征多 | 带 L1 正则的逻辑回归 | L1 自动做特征选择 |
| 类别极度不平衡 | LightGBM + `scale_pos_weight` | 内置样本权重处理 |
| 需要概率输出 | 逻辑回归 / 校准后的 XGBoost | 天然输出概率 |

### 回归任务
| 场景 | 推荐模型 | 理由 |
|------|---------|------|
| 线性关系为主 | 线性回归 / Ridge / Lasso | 简单可靠 |
| 非线性关系 | XGBoost / LightGBM 回归 | 树模型天然处理非线性 |
| 长尾目标变量 | 对目标做 log 变换 + 线性回归 | 压缩长尾 |

### 聚类任务
| 场景 | 推荐模型 | 理由 |
|------|---------|------|
| 聚类数已知 | K-Means | 速度快，可解释性好 |
| 聚类数未知 + 小数据 | 层次聚类 + 树状图 | 可视化确定 K 值 |
| 复杂形状聚类 | DBSCAN | 密度聚类，自动识别噪声 |
| 高维数据 | 先 PCA 降维 → K-Means | 降维去噪效果更好 |

### 时间序列预测
| 场景 | 推荐模型 | 理由 |
|------|---------|------|
| 趋势+季节性强 | Prophet | 自动捕捉，鲁棒性好 |
| 短期预测 + 多变量 | LightGBM（时间特征工程） | 树模型在特征工程后效果出乎意料地好 |
| 长期预测 + 深度学习 | LSTM / Transformer | 长序列建模 |

**代码生成结构**：
1. **导入库和设置** → sklearn/xgboost/lightgbm/prophet 等
2. **数据加载和初步探索** → 基本信息、缺失检查
3. **数据预处理** → （委托给 feature_engineering_skill 的逻辑）
4. **训练/测试拆分** → 分类回归用 `train_test_split`，时间序列用时间点切分（不要随机切！）
5. **模型训练** → 包含交叉验证
6. **模型评估**：
   - 分类：混淆矩阵、Precision/Recall/F1、ROC-AUC、PR-AUC（不平衡时 PR-AUC 比 ROC 更有意义）
   - 回归：MAE、RMSE、R²、MAPE
   - 聚类：轮廓系数、Davies-Bouldin 指数、肘部法
   - 时间序列：MAE、RMSE、MAPE、残差自相关检查
7. **特征重要性** → 输出 Top N 重要特征及分数
8. **模型保存** → joblib/pickle 保存最佳模型

**关键注意事项**：
- **时间序列禁止随机拆分**：必须用时间点切分（过去训练，未来测试）
- **数据泄露检查**：确保训练集和测试集之间没有信息泄露
- **类别不平衡**：分类任务中检查正负样本比例，< 1:3 时考虑 SMOTE/样本权重/阈值调整
- **模型校准**：需要概率输出时调用 `CalibratedClassifierCV`
- **超参调优**：优先用 Optuna（比 GridSearch 快 10x+），给出调优代码模板

**输出格式**：
````
## 任务判断
- 任务类型：<分类/回归/聚类/时间序列>
- 目标变量：<列名>
- 评估指标：<指标名> — <选择理由>

## 推荐模型
| 模型 | 适用理由 | 优点 | 缺点 |

## 建模代码
```python
# 1. 数据准备
# 2. 预处理
# 3. 训练/测试拆分
# 4. 模型训练 + 交叉验证
# 5. 评估
# 6. 特征重要性
```
````

## 3.2 Manager 设计

### MysqlManager
- 管理 MySQL 连接池（数据库连接信息从应用配置/Nacos 获取）
- 提供只读查询方法：`query(db_name, sql, timeout_seconds=30)` → 返回结果集
- 内置安全限制：禁止写操作（INSERT/UPDATE/DELETE/DROP/ALTER/TRUNCATE）
- SQL 注入防护：参数化查询，参数通过占位符传入，内部用驱动自带参数绑定
- **大表保护**：
  - 统计类查询统一加 `MAX_EXECUTION_TIME` hint（MySQL 5.7+）或 `statement_timeout`（PG）
  - 采样策略：根据 `information_schema.TABLES.table_rows` 估算行数，自动决定采样比例
  - 分位数用近似算法（`PERCENT_RANK` 窗口函数 + 分段采样），不直接用 `PERCENTILE_CONT`（MySQL 无原生支持）
  - 所有聚合查询默认加 `LIMIT`（返回行数上限 10000）

### CsvManager
- 管理文件读取（限定在配置的 `data_dir` 安全路径内）
- `read_info(file_path)` → 返回基本统计（复用 stats_engine）
- `read_sample(file_path, limit)` → 返回前 N 行
- 自动检测编码（chardet/cchardet）
- **大文件保护**：
  - 文件 > 500MB：拒绝全量读取，强制走采样通道
  - 采样策略：不等距跳过（按文件比例跳过随机偏移后顺序读块），避免 seek 风暴
  - 行数估算：大文件不逐行计数，用文件大小 ÷ 前 1000 行平均行长来估算

### StatsEngine
- `compute_numeric_stats(series)` → 均值/方差/分位数等（支持采样模式，返回近似值并标注）
- `compute_categorical_stats(series, max_distinct=10000)` → 频率统计，去重超过 `max_distinct` 时截断并标注
- `compute_correlation(df, max_cols=15)` → 相关性矩阵，超过 `max_cols` 列时只取前 N 列数值列
- `format_stats(stats_dict)` → 格式化输出为字符串（给 Tool 的 `execute` 返回用）
- **统一采样策略**：
  - 输入数据量 < 10万行 → 全量计算
  - 10万-50万行 → 10% 等距采样
  - 50万-200万行 → 5% 等距采样
  - > 200万行 → 1% 等距采样
  - 所有采样结果在 key 前缀加 `~`（如 `~mean`）并在输出中标注 `≈估算值`

## 3.3 大表 / 宽表处理策略总结

### 判断阈值

| 场景 | 判定条件 | 触发动作 |
|------|---------|---------|
| 大表（MySQL） | `table_rows` > 100万 | 自动降级采样（100万→30%, 500万→10%, >1000万→1%） |
| 大文件（CSV） | 文件大小 > 50MB 或行数 > 50万 | 自动降级采样（50万→30%, 200万→10%） |
| 宽表（MySQL） | 列数 > 30 | 自动剪裁到 20 列（数值→时间→低基数列优先） |
| 宽表（CSV） | 列数 > 50 | 自动剪裁到 30 列 |
| 超大文件（CSV） | 文件 > 500MB | 强制采样，禁止全量 |

### 降级信息透明化

所有自动降级都在返回结果首行明确标注，例如：
```
[采样率 10%，全量约 2300 万行] [已跳过 17 列: col_a, col_b, ...] [相关性计算已跳过——需要全量数据]
```

这样模型能明确知道当前看到的是估算值还是精确值，从而在生成分析代码时做出正确判断（比如提示用户某些指标需要全量计算）。

### 参数控制

两个 stats 工具都暴露了 `sample_pct` 和 `timeout_seconds` 参数：
- 用户急需精确值时可手动设 `sample_pct=100`（由 Manager 判断是否安全执行）
- `timeout_seconds` 默认 30s，大表统计可放宽到 60s
- `columns` 可精确指定要统计的列，绕过自动剪裁

## 3.4 Tool 与 Manager 的关系

Tool 是 LLM 的入口，Manager 是实际干活的。Tool 的 `execute` 方法调用 Manager：

```
LLM → Tool.execute(params) → MysqlManager.query(sql) / CsvManager.read_xxx() → 格式化字符串 → ToolResult
```

Tool 不直接写 SQL 或操作文件，只做参数校验、调用 Manager、格式化结果。

## 3.4 数据库连接配置

MySQL 连接信息放在应用配置中（环境变量或 Nacos），不在 Tool 参数中暴露：
```yaml
data_analysis:
  mysql:
    host: xxx
    port: 3306
    user: readonly_user
    password: xxx
    databases: ["db1", "db2"]  # 白名单，只允许访问这些库
  csv:
    data_dir: /data/csv_files   # 安全路径，只允许读这个目录下的文件
    max_file_size_mb: 500
```

# 四、设计对比与改进总结

| 维度 | 原方案 | 改进后 |
|------|--------|--------|
| 命名 | `describe_table_stats` 同时用于 MySQL 和 CSV，参数不同但名字相同 | MySQL 用 `describe_table_stats`，CSV 用 `describe_csv_stats`，清晰区分 |
| 编号 | 跳过了 5 号 | 编号连续 1-9 |
| 工具覆盖 | 7 个工具（MySQL 4 + CSV 3） | 9 个工具（MySQL 4 + CSV 3 + 通用辅助 2） |
| Skill 深度 | 骨干步骤，缺少具体指导 | 每个 Skill 都有：步骤、约束、图表/模型选择指南、输出格式模板 |
| 模型选型 | 用户写"我也不清楚" | 提供了分类/回归/聚类/时间序列四类任务的模型推荐表和选择理由 |
| 报告生成 | 用户写"我也说不好" | 提供了面向三种受众（技术/业务/管理层）的差异化报告结构 |
| 特征工程 | 只有框架 | 详尽的分类型处理指南（缺失值/数值/类别/时间/文本），含方法和适用条件 |
| 执行安全 | 未提及 | MySQL 只读限制 + SQL 注入防护 + CSV 路径安全 + 大文件保护 |
| 图表 | 只说"直方图、饼图..." | 完整的图表选择决策表 + 配色/字体/尺寸规范 |
| 架构 | 无实现指引 | 明确的目录结构、Manager 设计、配置方案 |

# 五、开源方案参考

如果后续发现某些 Skill 的积累还不够（尤其是 feature_engineering 和 modeling），可以考虑引入以下开源 Skill 作为参考或直接复用：

1. **pandas-ai** — 自然语言驱动的 pandas 操作，可参考其 prompt 设计。它的 `SmartDataframe` 对 describe/sample 的 prompt 组织方式值得借鉴。
2. **LangChain SQL Agent** — SQL 生成的 prompt 模板和工具链成熟，其 `SQLDatabaseToolkit` 中的 `InfoSQLDatabaseTool`、`ListSQLDatabaseTool`、`QuerySQLDataBaseTool` 与本方案的工具设计思路一致。
3. **ydata-profiling（原 pandas-profiling）** — 自动生成数据报告，其报告结构和统计项可以作为 `describe_csv_stats` 和 `report_skill` 的内容参考。
4. **LIDA (Microsoft)** — 自然语言到可视化的 pipeline，其图表推荐逻辑（根据数据特征自动选图）可以给 `plot_skill` 提供参考。

这些方案都是 Python 生态中的成熟项目，可以阅读它们的 prompt/SKILL 定义（如果有的话）来丰富本方案。
