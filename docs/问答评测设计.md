# 问答评测设计

针对 Text2SQL 问答质量的批量评测闭环（读库模式，实现于 `data/evaluate/eval.py`）。

## 1. 评测口径

- **无状态主口径**：每题独立会话重放，无历史记忆、无上下文参考，纯看推理与工具调用。可复现、可归因、与执行顺序无关。有状态 multi-turn（同 session 连问）与顺序强相关，作为独立题组后续补充
- **专用干净账号**：评测账号不得有跨会话 warm memory，否则记忆会劫持问题导致误答
- **走真实链路**：replay 走真实 HTTP chat 链路（leader 路由、hook、trace 全在），`trace_id = eval-{case_id}-{随机}`，评分据此关联回题目

## 2. 评测闭环

```
import-cases → replay → score → report
```

| 步骤 | 动作 | 数据流 |
|---|---|---|
| import-cases | 题集 JSON 导入题库（按 dataset+question upsert） | → `eval_datasets` / `eval_cases` |
| replay | 逐题调 chat API（每题独立会话），SSE 读到流结束，等 trace 落库 | → `traces` / `trace_spans` / `tool_semantics` |
| score | 取该 trace 全部成功 SQL，连业务库重执行与 gold 对比 | 读 `tool_semantics`，写 `trace_scores` |
| report | 聚合评分出 Markdown 报告 | 读 `trace_scores` |

- 语义数据自 `tool_semantics` 独立表读取（`tool_name='execute_postgresql'`，按时序），与 trace 骨架分离
- `score` 幂等：同一 trace 重评先清旧分，保证一份最新结果
- `score --trace-id` 评单条；`--since` 只评某时刻之后；`report --since` 控制聚合范围

## 3. 指标定义

| 指标 | 含义 | 单题取值 | 聚合 |
|---|---|---|---|
| **EX**（Execution Accuracy） | 执行准确率：agent 的 SQL 结果集与 gold 结果集一致 | 匹配=1，否则 0 | 均值 |
| **VES**（Valid Efficiency Score） | 效率分：gold 耗时 / agent 耗时 | `min(1, gold_time/pred_time)`，仅匹配 SQL 计算 | 均值 |
| **Valid SQL Rate** | 有效执行率：至少一条 SQL 成功执行（非语法/连接错误） | 1/0 | 均值 |

VES ≤ 1：agent 比 gold 快截断为 1，慢则按比例扣分。EX 是主指标，VES 与 Valid 为辅。

## 4. EX 判定口径

**候选制**：trace 内全部成功 SQL 按时序去重后逐条重执行，首个与 gold 匹配者判成功。理由：agent 常在给出最终 SQL 后再做复核/分页取全量等后续执行，只看最后一条会误判。`information_schema` 探查类 SQL 不会匹配 gold，跳过重执行。

**结果集匹配（rows_match）**：

- 值规范化：数值统一浮点格式（消除 100 vs 100.0）；`interval` 归一化为天数；字符串去空白并小写
- 多重集比较：忽略行序
- 列投影双向容错：gold 列名 ⊆ pred 列名，或 pred ⊆ gold（agent 多选列/中文别名不扣分）；等列数时列位组合投影兜底
- **top-N 并列**：gold 带 LIMIT 时，两侧去 LIMIT 比较全序（并列边界不稳定，逐行序比较会误判）

**业务库定位**：按候选 SQL 的 datasource、兜底题集 `db_name`；schema 路径（如 `business.dvdrental`）注入评分连接的 search_path。单条 SQL 执行超时 30s。

## 5. 失败归类

EX=0 时写入 category（trace_scores 的 EX 行 comment）：

| category | 判定 | 说明 |
|---|---|---|
| `no_sql` | 无 execute_postgresql 语义记录 | agent 未走 SQL 工具（如直接闲聊/卡死） |
| `sql_error` | 全部 SQL 尝试执行失败 | 语法/权限/超时，detail 含最后错误 |
| `db_unknown` | 无法确定目标库 | 题集与 trace 均无 db 信息 |
| `gold_error` | 金标准 SQL 自身执行失败 | 需人工修题，不算 agent 失败 |
| `result_mismatch` | 候选无一匹配 | detail 记录候选数、行数对比（最后执行 vs gold）与最后错误 |

## 6. 题库与报告维度

- 题目字段：`question`、`gold_sql`、`db_name`、`difficulty`（easy/medium/hard）、`ops`（如 agg/join/filter）、`grain`、`multi_hop`、`status`（verified/draft，replay 默认只重放 verified，`--all` 含 draft）
- report 输出三段：总览（EX / Valid SQL Rate / VES + 轮数）、失败归类表（EX=0 按 category 计数）、维度分组表（difficulty × ops × multi_hop 的 EX 均值）

## 7. 运行

```bash
# 导入扁平格式题集（question.json）
python data/evaluate/eval.py import-cases --file eval/evaluate_dvdrental/question.json \
    --name dvdrental --db business --status verified

# 重放（每题独立会话；--ids 选题，id 为题库自增主键）
python data/evaluate/eval.py replay --account <评测账号> --password <密码> --app-id app_0001

# 评分 + 报告
python data/evaluate/eval.py score
python data/evaluate/eval.py report
```

题集 JSON（扁平数组，`sql` 字段自动映射为 `gold_sql`）：

```json
[
  {"question": "统计一共有多少部电影", "sql": "SELECT count(*) FROM film",
   "difficulty": "easy", "ops": "agg", "multi_hop": false}
]
```
