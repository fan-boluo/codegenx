---
name: Code Review 反馈规则
description: 用户偏好：PR 评论要附带具体行号和修改建议，不要只说“这里有问题”
type: feedback
---

**规则**：给用户的 PR 提意见时，必须指向具体代码行，并给出至少一个可行的修改示例。

**Why:** 用户曾在团队中遇到过于笼统的 review 评论（如“这个函数太长了”、“命名不好”），导致反复沟通低效。用户期望 reviewer 能直接指出“第 45-60 行可以提取为 validateInput()，建议改成 ...”。

**How to apply:** 当用户提交 PR 让你帮忙 review，或你主动检查代码改动时，遵循此规则。如果无法确定具体行号，先询问用户或使用工具定位。
